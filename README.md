# Desa Harmonis 2 — живой рекламный дашборд

Интерактивный отчёт по рекламе Meta (Facebook / Instagram) для проекта Desa Harmonis 2.
Данные тянутся из рекламного кабинета **W_RES** (`act_1113679997274561`) через Meta Marketing API
**и** из выгрузки CRM в Google-таблице, джойнятся по UTM, обновляются каждые 3 часа и
публикуются на GitHub Pages за паролем.

## Что внутри
- KPI: расход, лиды, CPL, **квал-лиды, цена квал-лида (CPQL)**, % квалификации + план/факт месяца.
- Полоса качества данных: сколько лидов CRM удалось сопоставить с рекламой и почему остальные — нет.
- Динамика по дням, воронка (показы → клики → лиды → квалы), потоки **EN / DE / RU**.
- **Статусы сделок** из CRM и **география лидов** с процентом квалификации по странам.
- Кампании с дрилл-дауном: кампания → адсет → объявление, с квалами и CPQL.
- **Галерея креативов** — постеры 9:16, сортировка по квалам / CPQL, живое превью Meta в модалке.

## Стек
Vite + React + TypeScript + Tailwind v4 + Recharts. Данные — один зашифрованный файл
`public/data/latest.enc` (AES-256-GCM, ключ из пароля через PBKDF2). Сборщики — Node 18+
без внешних зависимостей.

## Локально
```bash
npm install
npm run data       # Meta + CRM + шифрование одной командой
npm run dev        # http://localhost:5181/desa-dashboard/
```

`npm run data` = `fetch-meta.mjs` → `fetch-crm.mjs` → `encrypt-data.mjs`.
Для шифрования нужна переменная `DASHBOARD_PASSWORD`.
Токен Meta берётся из `~/.config/claude-meta/token.env` или из `META_ACCESS_TOKEN`.

## Как обновляются данные

Каждые 3 часа GitHub Actions запускает оба сборщика **в одном прогоне**, поэтому реклама
и CRM всегда из одного среза и не расходятся между собой.

**Meta** — `scripts/fetch-meta.mjs`, Graph API. Настройки: `META_ACCOUNT_ID`, `MIN_DATE`,
`LEAD_TYPE`, `PLAN_BUDGET`, `PLAN_LEADS`, `PLAN_CPL`, `PLAN_QUAL`, `PLAN_CPQL`, `PREVIEW_FORMAT`.

**CRM** — `scripts/fetch-crm.mjs` читает вкладку `client_data` Google-таблицы обычным
`fetch` CSV-экспорта. Таблица открыта на чтение по ссылке, поэтому **не нужны** ни OAuth,
ни сервисный аккаунт, ни API-ключ. Настройки: `SHEET_ID`, `SHEET_TAB`.

Страница показывает срез на момент последней сборки (максимум 3 часа), браузер клиента
в Google не ходит. Нужно прямо сейчас — кнопка **Run workflow** в Actions, ~2 минуты.

### Как устроен джойн

У всех объявлений в `url_tags` стоит
`utm_source=facebook&utm_campaign={{campaign.name}}&utm_content={{ad.name}}`,
поэтому колонка `UTM Campaign` — это имя кампании, а `UTM Content` — имя объявления,
и они сходятся с API по точному совпадению (регистр игнорируется).

Квал-лид — значение `Qualified` в **колонке F** (`Квалификация`).
Колонки читаются **по индексу, а не по имени**: в шапке есть вторая колонка с тем же
именем `Квалификация` (Z) с другой логикой, и поиск по имени взял бы не ту.

Строки, которые не удалось сопоставить, не выбрасываются молча — они попадают в блок
`unmatched` с причиной и видны в интерфейсе. Лиды со старых флайтов (вне окна дашборда)
в CPQL не считаются: их расхода в окне нет, иначе цена квала была бы занижена.

### Проверки

`fetch-crm.mjs` падает, если сломалось что-то структурное: не тот таб, изменилась шапка,
ноль строк в окне, match-rate ниже 50%.

Это важно, потому что **gviz не отдаёт 404 на неверное имя вкладки — он молча возвращает
первую вкладку**. Без проверки шапки пайплайн зашифровал бы мусор и никто бы не заметил.

```bash
npm run crm:verify   # сверка с эталонным срезом 25.07.2026
```

## Деплой (GitHub Pages + авто-крон)
1. Создать репозиторий **`desa-dashboard`** (имя важно — под него настроен `base` в `vite.config.ts`).
2. Settings → Pages → Source = **GitHub Actions**.
3. Settings → Secrets and variables → Actions:
   - Secret `META_ACCESS_TOKEN` — системный токен Meta.
   - Secret `DASHBOARD_PASSWORD` — пароль входа в дашборд.
   - Variable `META_ACCOUNT_ID` = `act_1113679997274561`.
   - Variable `SHEET_ID` = id Google-таблицы с выгрузкой CRM.
4. `git push` → workflow соберёт и опубликует сайт, дальше пересборка каждые 3 часа.

Итоговая ссылка: `https://<user>.github.io/desa-dashboard/`

## Безопасность
Расшифровка происходит в браузере: неверный пароль — данные просто не расшифруются,
обойти через DevTools нечего. В репозиторий не попадают ни токен, ни `.data/latest.json`,
ни постеры — всё пересобирается в CI при каждом прогоне.

Отдельно стоит держать в голове: сама Google-таблица сейчас **читается любым, у кого есть
ссылка**. Если закрыть доступ, сборка упадёт — тогда нужен сервисный аккаунт + Sheets API
с JSON-ключом в GitHub Secrets.

## Оговорка по квал-лидам
В выгрузке есть только дата создания лида, даты квалификации нет. Квал привязан к дате
создания, поэтому цифры за последние дни ещё дорастут — свежий CPQL всегда выглядит хуже,
чем окажется через неделю.
